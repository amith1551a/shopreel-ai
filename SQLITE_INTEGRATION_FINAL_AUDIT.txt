Status:         [PASS] Data persists across close/reopen

Mechanism:
- SQLite transactions with atomicity guarantee
- PRAGMA foreign_keys = ON (strict mode)
- Mutex lock in BudgetGuard (thread-safe)
- timeout=15 seconds (handles concurrent access)
- Automatic rollback on exception (no partial commits)

Guarantees:
✓ No double-charging (atomic reservations)
✓ No budget loss (transactional ledger)
✓ No race conditions (mutex + timeout)
✓ No data corruption (SQLite integrity)

Example Flow - Job Submission:
1. User submits job
2. BEGIN TRANSACTION (implicit)
3. Check daily limit: $0.60
4. Check monthly limit: $20.00
5. INSERT into budget_ledger (RESERVED but not charged)
6. UPDATE budget_daily_summary (pending_cents += reserved)
7. COMMIT (explicit transaction end)
   → If all OK: Data written to disk (survives restart)
   → If error: ROLLBACK (no charge, safe to retry)
8. Return success to user
9. App receives Higgsfield job completion
10. BEGIN TRANSACTION (new transaction)
11. UPDATE budget_ledger (actual_cents = final cost, status = 'completed')
12. UPDATE budget_daily_summary (used_cents += actual, pending_cents -= reserved)
13. COMMIT
    → Cost finalized and persisted
    → Survives app restart

If app crashes at any point:
- Incomplete transactions auto-roll back
- Budget reserved but not charged = safe for retry
- Budget charged = data on disk (survives restart)
- Never double-charge (UNIQUE constraint on job_id)
